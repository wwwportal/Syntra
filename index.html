Yassine Amraoui

  1. Introduction

    How this research arrived where it is. It began with a question the Quran raises about itself — it claims to be clear guidance, to contain signs, to explain all things, so what does it actually ask of a reader? This chapter traces the path from that question through the dead ends, the tools that turned out to be wrong for the job, and the insights that survived.

  2. Organic Quranic Methodology

    The interpretive rules everything else is built on. The central commitment is to define Quranic terms using only the Quran itself, letting usage across all 6,236 verses settle meaning rather than deferring to hadith, biblical parallels, or traditional lexicons. Also covers the NCU framework, self-centric reading of the narratives, and how a claim is put at risk of falsification rather than merely asserted.

  3. Background

    What has already been tried. Part A follows the history of Quranic computation from hand-built concordances through Lane's lexicon to the digital corpora of the 2000s and today's neural models. Part B reviews the current research landscape in Quranic Arabic NLP — annotated corpora, morphological segmentation, root extraction, question answering, and where large language models still fail on this text.

  4. Architecture

    How the four kalima projects fit together into one system. A request enters through an MCP client, reaches the kalima-mcp server, and draws its data from kalima-db and its computation from kalima-math. This chapter maps those boundaries, traces a query end to end, and names the external services each piece depends on.

  5. kalima-db

    The dataset underneath everything else: a SQLite database holding the Quranic text with full morphological annotation — root, lemma, part of speech, pattern, and dependency relations for every segment. It ships from HuggingFace and downloads on first use, so no analysis here depends on a service staying online.

  6. kalima-mcp

    The server that makes the rest of the system usable from an ordinary AI client. It speaks the Model Context Protocol, exposing kalima-math's capabilities as tools backed by kalima-db. Includes the Quran DSL specification: the reference format, the linguistic layers a verse can be read through, the response shapes, and the invariants a well-formed answer has to satisfy.

  7. kalima-math

    The mathematical core. Every Arabic root is given a 127-dimensional fingerprint built from how it is actually used grammatically across the Quran, normalized into a probability distribution. From there the framework builds verse dynamics, an su(2) gauge field, and a UOR ring substrate — and closes by stating plainly what these structures can and cannot be taken to show.

  8. kalima-ml

    The argument that training a model should not require a GPU cluster or a budget. The ability to build AI is currently locked behind expensive hardware and specialist knowledge, and that decides who gets to ask questions of their own data. This chapter sets out the case, the obstacles in the way, the approach being taken, and how to take part.

  9. References

    The full bibliography: 50 sources spanning annotated corpora, morphological analysis, Arabic and Quranic NLP, and the mathematical background the framework draws on. Each entry links out to its origin and carries a number that the other chapters cite directly, so any claim made elsewhere on this site can be traced back to whatever it rests on.
